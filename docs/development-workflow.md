# Development Workflow

## Development Process

1. Select an assigned GitHub issue.
2. Create a new branch from `main`.
3. Name the branch using the issue number and a short description.
4. Implement the requested changes.
5. Open a draft Pull Request.
6. When the changes are ready for review, mark the Pull Request as ready for review.
7. Request a review from another team member.
8. Address any requested changes if necessary.
9. Squash the branch changes into one commit before merging.
10. Once approved and there are no merge conflicts, merge the Pull Request into `main`.

Once Continuous Integration (CI) is available, Pull Requests should only be merged after all required checks have passed.

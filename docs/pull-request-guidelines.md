# Pull Request Guidelines

Every Pull Request should:

- Be linked to the corresponding GitHub issue.
- Include a short summary describing the implemented changes.
- Be opened as a draft first.
- Be marked as ready for review only when the changes are ready.
- Be reviewed by at least one team member before merging.
- Have no merge conflicts with the `main` branch.
- Contain one final squashed commit before merging.

## Required Checks

Once CI is configured, Pull Requests should only be merged after all required checks have passed successfully.

The expected checks will include:

- Backend CI
- Mobile CI
- Additional checks may be added as the project evolves.
